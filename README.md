## 현재 개발·평가 범위

**외부 AI 기준 수요 → 규칙 기반 요금 정책 → A/B 선택·대기 시뮬레이션 → 충전 부하 집중 변화 리포트**입니다. 실측 배전망 피크 저감이나 정책의 인과 효과를 입증하는 도구는 아닙니다. 강화학습·LLM 관제·배전망 해석·3곳 이상 충전소는 후속 범위입니다.

두 탭은 구분합니다. 요금 관제는 충북 11개 시·군의 수집 상태와 대체 거점을 표시합니다. 수요 분산 시뮬레이션은 같은 종류의 두 충전소에서 고정요금 / 할인·할증 / 할인 전용 정책을 비교합니다. 관제 슬라이더와 시뮬레이션 설정은 독립적이며 시뮬레이션에는 시간대 배수를 적용하지 않습니다.

## 실행 순서와 AI 연결 상태

1. 실제 데이터 모드에서 지역·급속/완속·A/B를 고릅니다. 초기 A/B 추천은 좌표상 근접 기준이며 선택 후 양방향 도로 경로를 조회합니다.
2. **AI 수요 모델 연결**을 누릅니다. v2 검증이 성공하면 신규 인원·기간은 자동으로 채워지고 ‘추정값’이 됩니다.
3. 충전량은 제주 평균, 실제 데이터의 시간 방식은 **충전 시작·종료 기록 기반 추정**이 기본입니다. 기록은 실행 시 자동 조회하거나 별도로 먼저 조회할 수 있습니다.
4. 기본 급속 채택 행동계수 1/950/360/7200과 요금 정책·반복·시드를 확인하고 **시뮬레이션 실행**을 누릅니다.
5. 정책 비교와 부하 리포트를 확인하고 HTML/CSV로 같은 입력·근거를 함께 저장합니다.

**AI 연결 확인 필요는 수동으로 숫자를 입력하라는 뜻이 아닙니다.** v2에서 예측이 없거나 검증에 실패하면 인원·기간을 비우고 연결 필요/실패 이유·수신 생성 시각을 표시합니다. 이전의 24명·60분을 AI 예측처럼 사용하지 않습니다. 연결 버튼은 모델을 재학습하거나 원본 수집 작업을 실행하는 버튼이 아니라 공개 JSON을 다시 읽는 버튼입니다.

2026-11-04 19:46(한국 시각) 점검에서는 [v2 공개 파일](https://ev-hackathon.github.io/data/forecast_v2.json)과 [상태 저장본](https://ev-hackathon.github.io/data/status.json)이 모두 17:15 버전이었습니다. 원본 최근 실행 목록도 17:15 이후 새 실행을 보여주지 않았습니다. 이는 당시의 관찰이며 영구 장애라는 뜻은 아닙니다. 최신 파일이 갱신되면 다시 연결합니다. 재연결해도 생성 시각이 같다면 모델/수집 담당자가 원본 Actions의 예약·수집·예측·배포 단계를 확인해야 합니다. 정확한 중단 원인은 실행 목록만으로 단정하지 않습니다.

**같은 날 23:36 재확인에서는 갱신이 재개되어 예측·청주시 상태 모두 23:30 버전과 최근 배포 성공을 확인했습니다.** 최신 저장본을 다시 받은 로컬 화면에서 v2 자동 인원·기간 입력이 정상 동작했습니다. 앞의 지연 기록은 과거 진단 사례이며 현재 장애를 상시 선언하는 내용이 아닙니다.

v2는 **예측 생성 후 90분 이내**, **초기 상태 수집 후 45분 이내**, **남은 예측 구간 1분 이상**을 요구합니다. 미래 생성·시작 시각은 5분 이내 시계 오차만 허용합니다. 오래된 예측의 시각을 바꾸거나 제한을 풀어 현재 예측으로 쓰지 않습니다. 현재 모델 연결이 불가능해도 ‘현재 수집 상태 + 수동 수요’로 마지막 수집 시각을 명시한 가정 실험을 할 수 있습니다.

## 자동 입력과 남은 가정

| 항목 | 현재 처리 | 팀이 결정할 일 |
|---|---|---|
| 초기 충전기 상태·위치 | 수집값, 시각 표시 | 비교할 A/B·종류·기간 선택, 상태 품질 확인 |
| 이용률·신규 수요·기간 | v2 구간별 이용률·기대 충전 시작 건수, 남은 기간 | 충전 시작 건수를 도착 수요 대용으로 사용하는 한계 채택 |
| 충전량 | 제주 평균 급속 14.82 / 완속 16.24kWh | 팀 채택 제주 기준, 0.5/1/1.5배 민감도 및 지역 이전 한계 |
| 신규 충전시간 | 최근 완료 기록의 경험분포 | 팀 채택 완료 기록 방식의 정제·대체·보정 품질 검토 |
| 초기 잔여시간 | 기록 기반 정상상태 추정 | Durrett(2012) 근거로 채택, 진행 중 시작시각 없음·정상상태/표본 한계 검토 |
| 행동계수 s / α / β / τ | 급속 팀 채택 1 / 950 / 360 / 7200이 기본. 기존 1 / 600 / 300 / 2000은 비교용, 완속은 예시 가정 | 채택 근거 관리·국내 선택/설문 검증·민감도 범위 보강 |
| 할인 / 할증 / 여유 기준 | 20% / 15% / 빈 충전기 50% | 정책 비교로 선택, 행동계수와 별개로 결정 |
| 거리 | OSM/OSRM car A→B·B→A 추정 | 실제 우회거리 대리값·이동시간 미반영 가정 검토 |
| 전력·리포트 | 15분 일정 등가 부하, 같은 시각 A+B | 실제 순간전력·배전망 성과와 구분 |
| 반복·시드 | 100회 / 42 | 재현 조건 고정, 다른 시드에서 결론 확인 |

행동계수는 피크가 잘 줄어드는 숫자를 골라 ‘추정’하지 않습니다. 정책은 같은 행동·수요 조건에서 피크·대기·이동·요금·단순 매출을 함께 비교해 선택합니다. 모든 계수와 τ의 상대적 척도를 고려하며, 팀 채택 문헌 기준은 급속 기준 시나리오이며 검증된 충북 대표값·정확도 우위·최적값이 아닙니다. 완속 변경 시 별도 예시 가정으로 전환하며 자동 복귀 상태에서는 급속으로 돌아오면 채택 기준을 복원합니다. 직접 프리셋/계수를 수정하면 사용자 선택을 우선합니다.

## 완료 기록 기반 충전시간

[원본 공개 history 세션 기록](https://github.com/ev-hackathon/ev-hackathon.github.io/tree/history/history/sessions)을 브라우저에서 읽습니다. 초기 상태 수집 시각을 분석 기준으로 하여 이후 종료된 기록은 사용하지 않습니다. 최근 30일의 `statId,chgerId,speed,start,end,minutes`를 정제하고, 1~1440분·시각 일치·중복·종료 충돌을 검사합니다.

- 같은 충전소·종류 5건 이상 → 같은 지역·종류 5건 이상 → 출력 기반 가정 순으로 대체합니다. 5건은 처리 규칙이며 통계적 신뢰성을 보장하지 않습니다.
- 신규 시간은 경험분포에서 추출합니다. 진행 중인 세션의 현재 시작시각은 연결된 공개 자료에 없어 초기 잔여는 **총시간 길이 비례 표본 + 균등 잔여 비율**로 추정합니다. 긴 세션이 점유 중 관측되기 쉬움을 반영한 정상상태 가정입니다. 팀은 Durrett(2012) 잔여수명 이론을 근거로 이 방식을 채택했으며 실제 잔여시간을 복원한 것은 아닙니다. 출처·식·적용 한계는 행동계수 문서와 리포트 근거표에 표시합니다.
- kWh를 시간에서 역산하지 않습니다. 별도 E를 공급할 때 대표 출력을 넘지 않도록 총시간을 `max(기록 시간, 60×E/대표kW)`로 보정합니다. 초기 전력도 `60×E/보정 총시간`, 잔여 에너지는 `E×잔여/총시간`입니다.
- 표본 수·원평균·분위수·적용 평균·잔여 기대·연장 표본/차량 수·출처 커밋을 화면·리포트에 보존합니다. 수집 초기 편향, 비충전 점유, 장소·출력·차종 혼합은 남습니다.

실제 화면 기본은 `sessions`, 예시 모드 기본은 `power`입니다. 저수준 엔진의 기본은 자료 없이도 실행 가능한 `power`이며, `sessions`에는 `sessionPlan`이 필요합니다. `assumed`는 20~40분 비교용 가정입니다.

## 정책·민감도·부하 리포트

선택 비용은 `C=s×E×단가+α×추가거리+β×예상대기`, 선택 확률은 안정적으로 계산한 `exp(-C/τ)` 비율입니다. 충전기별 다음 사용 가능 시각을 관리해 도착순 배정과 대기를 계산합니다. 취소·포기·재이동·이동 소요시간은 제외합니다.

빈 비율은 `빈/(빈+충전 중)`이며 고장·미확인은 분모에서 제외합니다. 기본 50% 이상이면 여유, 빈 충전기가 남지만 기준 미만이면 보통, **이용률 100%일 때 혼잡**입니다. 여유 기준은 할인 대상 경계이며 혼잡 이용률 80% 같은 별도 설정은 없습니다.

v1은 1시간 후 이용률로 단가만 정하고 수요는 수동입니다. v2는 원래 A/B별 독립 포아송 건수와 구간 내 균등 도착을 가정하며, 차량 도착 구간 단가를 종료까지 적용합니다. 요약 단가는 시간가중 평균입니다. 지난 구간을 제외하고 첫 부분 구간의 건수는 남은 시간 비례로 조정합니다. 가격에 반응하는 수요 예측 모델을 재호출하는 폐루프는 아닙니다.

- **04 행동계수 비교:** 초기 예시·급속 채택 두 계수 묶음 × 세 정책. 같은 예측·차량·시간 난수를 공유합니다.
- **05 민감도 분석:** 한 항목씩 최대 8개 입력 수준, 현재값 자동 포함. 시간 방식 비교는 `sessions,power`이며 수동에서 인원 `12,24,36`도 비교할 수 있습니다. 비교 범위는 신뢰구간·최적값이 아닙니다.
- 초기 점유와 난수는 공유하되 시간 방식·충전량 변경 시 잔여시간은 해당 규칙으로 재계산합니다. v2 인원·기간은 민감도에서 수동 변경하지 않습니다.
- 리포트는 A/B·같은 시각 A+B의 15분 평균 등가 부하, 피크·저감률·SE·기간 이후 에너지·미완료 차량·최종 완료·대기·요금을 제공합니다. 신규·초기 차량 모두 완료할 때까지 계산합니다.
- 표는 반복별 최대값의 평균, 곡선은 반복 평균 시계열입니다. SE는 난수 반복 변동이며 모델·행동·자료 불확실성 전체가 아닙니다. 초기/신규 에너지를 보존하며 실제 충전곡선·효율·출력 공유·비충전 부하는 제외합니다.

## 개인 GitHub 배포와 원본 서비스

개인 저장소 `ms3011975/ev-hackathon.github.io`의 **main /docs**를 GitHub Pages로 배포합니다. 원본 조직 사이트를 덮어쓰지 않습니다. 개인 사이트에 자체 저장본이 없으면 원본 `https://ev-hackathon.github.io/data/`를 읽으며, 원본 갱신에는 개인 사이트 재배포가 필요하지 않습니다. 새 코드·문서는 개인 main에 푸시하고 Pages 배포 성공을 확인합니다.

`http://localhost:8000`은 상대방 PC를 가리켜 공유 주소로 사용할 수 없습니다. 위 개인 HTTPS 주소를 공유하세요. 주소에는 현재 설정·업로드 JSON이 저장되지 않으므로 동일 결과 공유에는 HTML/CSV와 실행 입력을 함께 전달합니다.

별도로 자체 수집 서비스를 운영하려면 기존 `.github/workflows/deploy.yml`과 `EV_API_KEY` Secret, history 브랜치, GitHub Actions Pages 배포 구성을 사용합니다. **이는 현재 개인 /docs 배포와 다른 구성**입니다. 현재 개인 사이트에 Secret이나 새 수집 서비스를 설정할 필요는 없습니다. 원본 모델은 제공 팀이 관리하며 이 개인 저장소는 공개 결과를 소비합니다.

## 로컬 실행·테스트

Python 3.10+와 Node.js를 사용합니다. 공개 JSON과 지도·경로·원기록 조회에는 인터넷이 필요합니다.

```sh
python -m pip install -r requirements-server.txt pytest
python -X utf8 -m scripts.build_web
python -X utf8 -m scripts.sync_public_data
python -m http.server 8000 --bind 127.0.0.1 --directory docs
```

`http://127.0.0.1:8000/#simulation`을 엽니다. `sync_public_data`는 인증키 없이 공개 상태를 `docs/data`에 복사하며 로컬 파일은 자동 갱신되지 않습니다. `docs/data`는 Git에서 제외합니다. 데이터 없이 예시 모드도 실행할 수 있습니다.

```sh
node --test tests/simulation.test.cjs tests/forecast-v2.test.cjs tests/behavior.test.cjs tests/routing.test.cjs tests/session-timing.test.cjs
python -m pytest -q --basetemp=.pytest_cache/simulation-run
```
